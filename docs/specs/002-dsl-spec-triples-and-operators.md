# uniparser2 Design · 02 DSL Spec: Triples and Operators

> **Status**: design draft v0.1, now located in `docs/specs/` and committed. **Upstream**: `00`, `01`.
> **What this document answers**: how a stage is written, what each position means, how references are written, which operators and actions exist, and what
> counts as a bad chain. **Source of truth**: the external syntax (the form written for humans and generated by an LLM) = **positional triples** (the direction
> settled by the `04` parser-syntax draft — the internal source material, not shipped in this repository); the internal representation = a **named-argument AST**
> (each operator declares its own parameter Schema; the D2 direction of the legacy `dsl-design` draft, likewise internal source material). The two are connected
> by a **compile-time** mapping table: the compact form saves tokens for the LLM, the named AST buys validation and locatable errors.

---

## 1. Stages: triples (unified slot order)

```jsonc
["<operator>", "<action>", "<parameter>"]
```

**The slot order is unified across all operators** — `[operator, action, parameter]`: slot 2 is the **behaviour** declared by that operator (a closed
enumeration; for a single-action operator it is the parameter itself), slot 3 is an **arbitrary value** (CSS selector / XPath / regex / actual argument).
`Op.slot_roles` only gives the positions their **names** (`up2 ops` prints them), and `Op.action_slot` is derived from the arity.

| Operator | Arity | Slot 2 | Slot 3 | Example |
|---|---|---|---|---|
| `css` / `css1` | 3 | accessor | CSS selector | `["css1", "@href", "a.download"]` |
| `xpath` | 3 | accessor | XPath expression, or `[expression, ns]` | `["xpath", "text", ["//dc:creator", {"dc": "…"}]]` |
| `re` | 3 | `search` / `findall` / `sub` | pattern, or `[pattern, group]` / `[pattern, replacement]` | `["re", "search", ["(\d{4})", 1]]` |
| `ctx` | 3 | `get` / `set` / `del` / `dict` / `list` | path / list / object | `["ctx", "get", "locals.x"]` |
| `py` | 3 | function name (allowlist) | the function's parameter(s) | `["py", "urljoin", "$globals.base_url"]` |
| `udf` | 3 | function name (host-registered) | — omitted (the stage writes 2 slots; the call is unary or nullary) | `["udf", "my_fn"]` |
| `json` | 2 | jmespath expression | — | `["json", "data.html"]` |
| `each` | 2 | field map, or one chain | — | `["each", {"title": [["css1","text","a"]]}]` |
| `code` | 2 | the source text | — | `["code", "len(obj)"]` |

> **The enumeration strength of the positions increases step by step**: slot 1 = an operator in the registry (closed); slot 2 = the behaviour declared by that
> operator (closed, except `css`'s `@<attribute>` and `udf`'s host-registered names); slot 3 = an arbitrary value (a literal, a reference, or a positional
> array of parameters). `udf`'s slot 2 is a function name the host leaves open — a deliberate extension point.

### 1.1 Length rule

A stage is `[operator]`, `[operator, parameter]` or `[operator, action, parameter]`. A **parameter slot is omitted** when the action has nothing required
left to fill (`["py","strip"]`, `["json"]`); it is never written as an empty placeholder. A missing required parameter is `UP2-E1005`; an extra slot is
`UP2-E1004`. There is no "one stage shape per operator": the operator's declaration says which slots mean what, and the parameter slot's shape is `value`,
`array` or `none` (`up2 ops` prints it).

> **Deviation record D-02-13 (the slot order of the triple)**: §1 of the `04` draft writes "all parsers are unified as `[parser, action, value]`", and its
> example `["css", "@href", "a.title"]` puts the action first; whereas the css spelling in the `01` data-structure draft / the `02` worked example is
> `["css1", "a", "@href"]` (selector first). This design at one point **declared the slot roles per operator** and turned css/xpath into "selector first", and
> then **withdrew** that flip, returning to the unified shape `[operator, action, parameter]` — selectors and XPath always land in slot 3.
>
> **Withdrawal reason one (increasing enumeration strength)**: `[operator, action, parameter]` is a rule with zero exceptions, and the enumeration strength of
> the three positions increases naturally (§1); after flipping to selector first, slot 2 would house both a "closed enumeration" and an "arbitrary value" at the
> same time, and that rule would be left with nothing but exceptions.
>
> **Withdrawal reason two (the tax of two shapes)**: the kernel would have to declare `action_slot` for every operator (instead of deriving it from the arity as
> it does now); diagnostics would have two JSON Pointer shapes (`/0/1` and `/0/2` could both point at the parameter position); and every css/xpath example in
> the documentation would need a parenthetical explaining which family of slot order it belongs to.
>
> **Deviation record D-02-1**: in the `04` draft `const` is 2-element and the rest are 3-element, so the shapes are inconsistent. This design unifies it as "the
> arity is declared by the operator Schema (2 or 3) and the length is matched exactly", rather than hard-coding it in a document.
>
> **Deviation record D-02-2**: the `04` draft passes multiple arguments as a comma-joined string (`["py","replace","\u65e7,\u65b0"]`, i.e. old and new glued
> with a comma). That is exactly the technique the legacy `dsl-design` draft lists as "R1, the root cause" (hiding arguments inside a string ⇒ no validation, no
> escaping, and it collapses the moment a value itself contains a comma). This design switches to a **positional argument array** and a **named argument
> object** (§4).

## 2. The three value forms of a slot

Once the `$` is removed, the strings that can appear in a slot are of exactly three kinds, discriminated by **position + the operator's closed enumeration**:

| Form | Meaning | Example |
|---|---|---|
| **Enumeration member** | a fixed behaviour built into the operator (a closed set; writing a wrong one is `UP2-E1002` and the available values are listed) | `text` / `nodes` / `search` / `get` / `remove` |
| **Open name** | a user-side name: `py`'s function name, `udf`'s function name | `urljoin` / `my_site_clean` |
| **`@` prefix** | only for `css`/`css1` **slot 2 (accessor)**: `@<attribute name>` means "take the attribute" | `@href` / `@content` (the single character `"@"` ⇒ `UP2-E1002`) |

> **Why the `$` prefix was removed** (D-02-14): `$` originally only marked "this is a reserved action". Slot 2 is now a closed enumeration declared by each
> operator and its members are checked against a set, so discrimination no longer needs a sigil; and `$` already has a definite meaning in the reference syntax
> (§3), so sharing it in both places invites misreading. The closedness of reserved actions has not weakened: an unrecognised enumeration value is still a
> compile error (`UP2-E1002`).

## 3. Reference syntax

### 3.1 Form

```
$<root>[.<segment>][.<segment>]…
```

| root | Meaning | Writable | Readable |
|---|---|---|---|
| `globals` | the story's constants plus this run's overrides | — | every node |
| `locals` | the current scope's variables (every field map writes here) | the current scope | the scope and its children |
| `public` | the run's shared notes | any node | any node |
| `in` | the current **node invocation's** input | — | that invocation |
| `obj` | the whole value the current stage received | — | that stage |

`$locals` was a second name for `locals` and is **retired** (change `rename-and-unify`): one namespace, one
spelling. A bundle that writes it is `UP2-E1006`, an unknown reference root.

**`$in` is the current node invocation's input** (`03` §2.2): at the top of a run it is the value the host
passed, at a `["node", name]` call it is the value the caller had, and inside an `each` it is still the node's
input — the element is the stage value. A dotted path reads a field of it (`$in.url`, `$in.status_code`).

**Identity is `[]`.** The whole-chain reference (`"$in"`, `["$globals.base", […] ]`) is **retired**: a chain is
an array of stages and the empty array is the only identity. A string in chain position is `UP2-E1004`.

- **Only dotted paths are supported, not array indices** (settled by Q24 in `01`). To take an index, use the explicit operator `["py","getitem",0]`.
- **Multi-level dotted paths** are supported (`$article.meta.url`).
- **There is no `<node name>` reference root**: a node's product is the value its call returns, and a field map writes every field into `$locals`. A standalone field chain may declare external product roots when it is compiled (`--product`); a story has no such roots.
- **A dotted path dispatches on the value it walks** (`03` §13 O12): a mapping is read by key, a sequence by a digit index and a host object by `getattr`.
  An attribute that is **callable** is refused with `UP2-E2002`, the same way `py.getattr` refuses one — a method is not a value, and it could not leave the
  run anyway (`UP2-E2003`); the fix hint names `["css","text",""]` or a `udf`.
- A `_`-prefixed field is a **local**: every field map writes every result into `$locals`, and the `_` prefix only keeps the field out of the product.
- **There is no iteration variable**: inside `each`'s field map the current element is the **input value** of every field chain (§6.9), and each element is
  evaluated in its own child scope — `$locals.*` falls back outward **by name** (the innermost scope holding the path's first segment resolves the whole path,
  so a name the element wrote is never read from the calling scope), while a write stays in the element.

### 3.2 When a string counts as a reference: decided by the parameter Schema, not by a global scan

Every parameter of every operator declares a **kind** in its Schema:

| kind | Meaning | Example |
|---|---|---|
| `ref` | must be a reference; a literal is a compile error | the path of `ctx.get` |
| `literal` | always a literal; a leading `$` does not make it a reference | `css`'s selector, `re`'s regex, URL templates other than `py.urljoin` |
| `ref_or_literal` | a string starting with `$` ⇒ a reference; otherwise a literal | `py`'s parameter slot (`["py","urljoin","$globals.base"]`) |
| `fields` | a **field map** (`field name → chain`), compiled recursively | `each`'s single argument |

**Why it has to be designed this way**: `$` is a legal character in regexes and CSS (`a[href$=".pdf"]`, the regex `$foo`). Deciding references by "scan the
whole document for strings starting with `$`" would damage real rules. Once the decision is made per parameter kind, ambiguity exists only in `ref_or_literal`
positions, and there it comes with one single escape form.

### 3.3 Escaping a literal that starts with `$`

To write "a literal that starts with `$`" in a `ref_or_literal` position, use a directive object:

```jsonc
{"$lit": "$100"}          // produces the string "$100"
```

**This is a direct answer to blocker R in the `02` worked-example draft** (the internal source material, not shipped in this repository): §7 of the `04`
parser-syntax draft mentioned `$get` without ever defining it, and the reference forms it used (`$locals.*` / a dotted path / a
plain literal) were all guesswork. This design's rule can be stated in one sentence:

> **A leading `$` ⇒ a reference; a literal starting with `$` uses `{"$lit": …}`; everything else is a literal.**

**The escape applies at every depth**, not only at the parameter slot: an object with exactly one `$`-prefixed key is a
directive wherever a `ref_or_literal` value is read, so `["py","or",[{"$lit":"$a"},"fallback"]]` quotes the text inside
the operand array too. Leaving it slot-only made such a literal
unwritable inside a container, and one failure mode was silent: a single-key object whose key is a directive the chain
did not mean came back as **data** — `{"$lit": "plain"}` in an array answered with the object itself. A `$`-prefixed
single-key object is therefore the escape or an error (`UP2-E1005`), never a value, and a `literal` parameter keeps a
leading `$` as text as before.

**`$get` is abolished** (it no longer appears anywhere in this design).

## 4. The parameter slot (slot 3)

> Terminology: the **parameter slot** is the position that carries the parameters — slot 3 of a 3-slot operator, or slot 2 of a single-action operator
> (`json` / `each` / `code`). Its position is `Op.param_slot` (= arity − 1), see §1.

| Form | Example | When |
|---|---|---|
| **Scalar / value** | `"a.title"` / `1` / `true` / `null` | the action's one parameter |
| **Reference** | `"$globals.base_url"` / `"$obj"` | the parameter comes from a scope or the stage value (only in `ref` / `ref_or_literal`) |
| **Positional array** | `["old", "new"]` | two or more fixed parameters, in declaration order |
| **Data object** | `{"pattern": …}` is **not** this | only where the parameter *is* a map: `each`'s field map, `ctx.dict`, xpath's namespace map |

**Decision order, fixed at compile time**:

1. A `$`-prefixed single-key object is a **directive** (`{"$lit": …}`), at every depth of a `ref_or_literal` parameter (§3.3).
2. **Zero parameters** left after the action slot's preset ⇒ the slot must be **omitted**; writing it is `UP2-E1004`.
3. **Exactly one** parameter left ⇒ the slot value **is** that parameter's value, a container included. An object written here is ordinary data,
   so an action whose parameter needs a scalar rejects it at compile time (`["py","urljoin",{"base":"…"}]` is `UP2-E1005` at `/0/2/base`; the accepted
   writing is `["py","urljoin","…"]`).
4. **Two or more** left ⇒ one **positional array** whose length is the declared arity (`["py","replace",["old","new"]]`); a trailing optional parameter
   may be omitted, a missing required one is `UP2-E1005` at `/0/2/<index>`. A bare scalar binds the first parameter (xpath's expression without a
   namespace map), and an object is `UP2-E1005` — an object is a data map, never a parameter list.

`up2 ops` reports the shape per action as `param_form` (`none` / `value` / `array`, see `01` §7), so a chain writer does not infer it from this table.
A parameter that genuinely accepts any JSON value keeps accepting containers (`["py","in",[200,301]]`; an array that is a *value* is distinguished from a
parameter list by the action's declaration, never by the shape alone).

## 5. Evaluation semantics of a field chain

A field = one ordered chain, written in one form:

```jsonc
"title": [["css","text","h1"], ["py","first"], ["py","strip"]]
```

Evaluation rules:

| Current state | Behaviour of the next stage |
|---|---|
| `Ok(v)` | feed `v` as the input of the next stage and keep evaluating |
| `Failed` | **stop the chain** and fail the run with the code of the stage that failed; nothing degrades it |

- The first stage's input = the field's `input` (the node's input by default; inside `each`'s field map it is the current element, §6.9).
- Fields are evaluated in **declaration order** (a JSON object preserves order), so a later field can reference the `_` local values produced by an earlier one.
- **The number of stages is a hard stability boundary**: exceeding `MAX_STEPS_PER_FIELD` is a compile error (`01` §9).

**A query that matches nothing is a value, not a state.** There is no third outcome and no per-action
flag (`empty-value-semantics`): every accessor answers the empty value of the shape it produces —
`""` for text, `[]` for a list, `None` for a node handle or a JSON query — and the chain keeps
evaluating. `py.or` is the fallback, because the upstream value is its first operand; a stage that
*fails* is never caught by it.

**A `try` directive guards the next stage** (`public-scope-and-try`): `["try","skip"]` /
`["try","break"]` / `["try","raise"]` protect **the stage immediately after them** and nothing else. On
a failure `skip` keeps the value the chain carried into that stage and carries on, `break` ends the
chain with that same value, and `raise` is the default behaviour. A guarded stage that **succeeds**
disarms the guard, so a `try` never swallows a later failure. The directive is **not** an operator — it
changes what the evaluator does with the next stage's outcome, so the operators stay pure — and it
never turns an exception into a value. Two directives in a row, or a directive at the end of a chain,
are compile errors (`UP2-E1005`): a guard that protects nothing is a mistake, not a no-op.

> **Deviation record D-02-3**: the `04` parser-syntax draft describes `remove` as "delete a node (a side effect)". This design removes side effects — `remove`
> returns a **pruned copy** as the input of the next stage, affecting only this field's chain. Reasons: (a) invariant I5 of `01` requires operators to be
> side-effect free, otherwise chains cannot be replayed and fields bleed into each other; (b) when `body` runs the fields over N items one by one, a shared
> mutable DOM means that the deletion made for one item affects the next — a trap that is bound to be stepped on. The cost is that every `$remove` needs one
> tree clone, for which a place has been reserved in the limits of `01` §9 and in the performance tests of `05` §4.4.

## 6. The complete set of operators

### 6.1 `css` / `css1` — selector (HTML)

**Slots**: `["css", accessor, selector]` — the accessor is in position 2 and the selector in position 3. The two operators **differ by one cardinality only**:
`css` takes a value from every match, `css1` only from the first match; the accessor table is a single shared one.

| Accessor | Selector kind | `css` (all matches) | `css1` (first match) |
|---|---|---|---|
| `text` | selector (literal) | `list[str]` (no match ⇒ `[]`) | `str` (no match ⇒ `""`) |
| `html` | selector | `list[str]` (no match ⇒ `[]`) | `str` (no match ⇒ `""`) |
| `outer` | selector | `list[str]` (no match ⇒ `[]`) | `str` (no match ⇒ `""`) |
| `@<attribute name>` | selector | `list[str]` (no match / attribute absent ⇒ `[]`) | `str` (attribute absent ⇒ `""`) |
| `nodes` | selector | `list[Opaque]` (no match ⇒ `[]`) | `list[Opaque]` (0 or 1) |
| `self` | selector | `Opaque` (first match; use `nodes` for all) | `Opaque` (no match ⇒ `None`) |
| `remove` | selector | a **copy** with **all** matches pruned (a pure function, see D-02-3) | a copy with the **first** match pruned |
| `exists` | selector | `bool`: true when at least one node matches | `bool` (the first-match flag does not change existence) |

- **`text` excludes the text of `script`/`style`/`noscript`** (the noise tags are pruned on the copy before the text is taken); it does not normalise whitespace
  (use `py.normalize_space`).
- **An empty selector `""` ⇒ take the current input itself** (do not search downward). This is the standard way to extract a value from each item inside
  `each`'s field map: `["css1", "@href", ""]` = take the `href` of the current element itself — `css1` lands on that `<li>`, and `""` says "do not look further,
  use it as it is".
- The input is a `str` (containing HTML) or a node (`Opaque`). **A list input reports `UP2-E2002`**: parsing item by item belongs to the chain-level structure
  (`each`, §6.9); doing it here would only yield a semantically murky "concatenation".
- **Nodes are always wrapped as `DomNode(Opaque)`**: native engine objects do not enter the value domain, so the products of `nodes` / `self` are naturally
  rejected by export packing (`UP2-E2003`).
- There is exactly one engine: **`selectolax`** (`requires=("selectolax",)`). Not installed ⇒ compile-time `UP2-E1107` + the install command.
- **XML is not its business**: XML uses §6.11's `xpath`. Measured, selectolax raises `ValueError: Bad CSS Selectors` outright for XML with prefixed namespaces
  (`dc|creator`), the unprefixed spelling (`dc\:creator`) yields `[]`, and it merges `<Item>` with `<item>`.

> **Deviation record D-02-11 (`css1` was once deleted and was later restored)**: at the end of L1 `css1` was deleted for a while, on the grounds that "it is
> equivalent to `css` + `py.first`, and the product shape should not depend on the operator name". **Three reasons for restoring it** (with more information in
> hand than at deletion time):
>
> 1. **`nodes` cannot shoulder "take all values"** — what it hands over is an `Opaque` handle, and in L1 nothing can be done with it except count it with
>    `py.len` (taking text requires acting on each item, and that is L2's fan-out). Its job is **to hand a set of nodes to L2 for fan-out** (a row that needs
>    several fields extracted must obtain handles), not to take values. Deleting `css1` would push "take all values" onto `nodes`, and that is wrong.
> 2. **"First match by default + an `all: true` switch" risks silent truncation**: forgetting the switch yields a "legal but only-the-first" value with no error
>    at all, whereas picking the wrong one of two operators fails **loudly** with `UP2-E2002`. Both cardinalities being explicit is more in keeping with "bad
>    things must not be silent".
> 3. **The performance reason must be stated accurately**: `css_first` is **not** a fast path (measured 1.0–1.1x over 5000–20000 matches — matching itself has
>    to walk the whole tree); the real gain is in the **value-extraction phase**, where the N-1 texts/attributes that are about to be discarded need not be
>    extracted (measured: `text` over 5000 `<a>` elements is 4.25 ms versus 108.9 ms).
>
> Cost: two names to remember (but the names state their own cardinality: `css1` = select_one), and one more `first_only` flag in the code (the accessor table
> is not duplicated). The `04` draft already had two parsers (§2.1/§2.2), so restoring it agrees with the source design.
>
> **Deviation record D-02-12 (dropping the belle-soup fallback engine)**: the original design let `css` choose between `selectolax` and `beautifulsoup4`
> (`any_requires`). Measured, the two have exactly the same semantics for HTML, and once XML had been handed to `xpath` (lxml) bs4 had no remaining duty; the
> `any_requires` mechanism had `css` as its only user (violating "do not build an interface for a single implementation"), so it was deleted.

### 6.2 `json` — dotted-path query (jmespath)

`["json", <jmespath path>]` (**2 elements**): it has only one behaviour (take a value along the path), so the action position is not written in the chain.

| Slot 2 | Product |
|---|---|
| a jmespath expression (literal, **pre-compiled at compile time**) | an arbitrary JSON value; no result ⇒ `None` |

An empty path `""` = take the root (settled by the `04` draft). The input may be a `str` (automatically `json.loads`-ed) or an already parsed value. The
registry still keeps one action name (`get`) to declare the parameter table and for the conformance audit, but it **does not appear in the chain**.

> **Part of deviation record D-02-14**: the `04` draft writes `["json", "$get", "data.html"]`. Since the only possible action is taking a value, the action
> position is pure redundancy; removing it makes the chain shorter (`["json", "data.html"]`) and consistent with `const`'s two-position form.

### 6.3 `re` — regex

**Slots**: `["re", action, pattern]` — the action is in position 2 and the pattern in position 3.

| Action | Slot 3 | Product |
|---|---|---|
| `search` | the pattern, or `[pattern, group]` | `group(0)` of the first match, or the named/ numbered group; no hit ⇒ `""` |
| `findall` | the pattern | `re.findall`; Python's tuples are encoded as **arrays**; no hit ⇒ `[]` |
| `sub` | `[pattern, replacement]` | every match replaced (`re.sub`), `\N` / `\g<name>` supported; no hit ⇒ unchanged |

- **`search`, not `match`**: the implementation is `re.search(...).group(0)` (find the first one from the start), whereas Python's `re.match` is **anchored**.
- `group` is folded into `search`: a pattern with no capture group needs no second element, and multi-group reformatting composes `search` with `sub`
  (`["re","search","(\\d{4})-(\\d{2})"]` then `["re","sub",["-","/"]]`).
- **`findall` follows Python exactly**: zero or one group answers the group values, two or more answer one tuple per match — the only change is that a tuple
  becomes an array, because the value domain is JSON.
- **`sub` replaces every match** (no `count`: a count is exotic and belongs in `code`). Every `\N` / `\g<name>` is checked against the pattern at compile
  time, so a bad reference is `UP2-E1005` before any text is touched.
- Regexes are always **pre-compiled at compile time**; nested quantifiers (the ReDoS shape) are rejected at compile time (`UP2-E1013`).
- **Measured correction**: Python's `re` has **no `timeout` parameter** (3.13/3.14), so there is no runtime regex timeout. ReDoS defence is the compile-time
  static check plus the input-size limit (`MAX_TEXT_BYTES`); the static check catches only the classic nested-quantifier shapes — an explicitly recorded gap.

### 6.4 `py` — allowlisted functions

Shape: `["py", "<function name>", <value | positional array>]`. A parameter-less function omits slot 3 (`["py","strip"]`); an action with two or more fixed
parameters takes **one positional array** (`["py","replace",["old","new"]]`, `["py","between",[200,300]]`). An object is a data map, never a parameter list.

**Which parameters are validated at compile time** (`UP2-E1005` + pointer + fix): a parameter that only accepts a scalar rejects a JSON container, a literal of
another type, and a string the runtime parses and refuses. A reference is only known during evaluation, so nothing is claimed about it. A **single-parameter**
function written with an object (`["py","urljoin",{"base": …}]`) is a compile-time `UP2-E1005`: the object is the *value*, see §4.

| Function | Parameter | Accepted |
|---|---|---|
| `urljoin` | `base` | a string |
| `slice` | `spec` | a slice notation (`":20"` / `"1:5"` / `"::-1"`) |
| `split` | `sep` | a string |
| `strip` | `chars` (optional) | a string |
| `getitem` | `at` | an integer or a string |
| `replace` | `old` / `new` | strings |
| `urlsplit` | `part` | the URL-part enum |
| `strftime` | `layout` | a non-empty, locale-free layout |
| `strptime` | `format` | a non-empty, locale-free format |
| `from_timestamp` / `to_timestamp` | `tz` | a number of hours (a bool is rejected) |
| `between` | `bounds` | a two-element array of numbers |
| `sleep` | `seconds` | a non-negative finite number |
| `filter` | `keep` (optional) | a boolean (the default is `true`) |

Deliberately not checked: `join.sep` (the runtime coerces it with `str()`), and a parameter that genuinely accepts any JSON value (`in`'s container,
`or`'s operand array). `or`/`and` also refuse a literal that is not an array at compile time; a reference to one is decided at run time (`UP2-E2002`).

**Function table (48 functions, a closed set; anything outside is `UP2-E1003`)**:

> **Dependencies are declared per action**: `html_to_markdown` needs `html-to-markdown`; when it is missing that **action** is unavailable (`UP2-E1107`)
> while the operator's other actions keep working. It accepts **no arguments** and has no base_url — complete relative links with `py.urljoin`.

| Category | Function | Arguments | Semantics |
|---|---|---|---|
| Literal | `const` | any JSON value | return the value verbatim (the former `const` operator) |
| Text | `strip` | `chars`? | strip whitespace, or the given characters |
| Text | `normalize_space` | — | collapse runs of whitespace into one space and trim |
| Text | `html_to_markdown` | — | HTML → Markdown (optional `[md]`; no options exposed) |
| Text | `replace` | `[old, new]` | replace all occurrences |
| Text | `split` | `separator` | split into a list (no `maxsplit`; truncate with `slice`/`first`) |
| Text | `join` | `separator` | list → str |
| Text | `upper` / `lower` | — | case conversion |
| Collections | `slice` | `":20"` / `"1:5"` / `"::-1"` | slice a string or a list |
| Collections | `getitem` | `at` | a sequence by index, a mapping by key, a str by character; no coercion; a missing subscript is `UP2-E2018` |
| Host object | `getattr` | attribute name | read a host object's own attribute; never calls a method; an absent one is `UP2-E2002` |
| Collections | `len` / `first` / `last` / `flatten` | — | size, first/last element, one-level flatten |
| Collections | `sort` / `sort_desc` | — | Python's `sorted` / `sorted(reverse=True)`; no key, no coercion |
| Collections | `uniq` | — | deduplicate while preserving order (a set plus a list) |
| Collections | `find_jsons` | — | every JSON object/array embedded in the text, parsed, in document order |
| Collections | `filter` | `keep`? | keep truthy elements (`true`, the default) or falsy ones (`false`); a new list in input order |
| URL | `urljoin` | `base` | relative → absolute |
| URL | `urlsplit` | `"netloc"` / `"path"` / `"query"` / … | take a URL apart |
| Encoding | `b64_encode` / `b64_decode` | — | Base64 |
| Encoding | `sha256` / `md5` | — | hexadecimal digest (checksums; md5 is not for security) |
| Time | `strptime` | `format` | text + explicit format → a `datetime` (naive, or aware with `%z`) |
| Time | `strftime` | `layout` | a `datetime` + layout → text (`%z` renders an aware offset, empty on a naive value) |
| Time | `from_timestamp` | `tz`? | epoch seconds → an aware `datetime` at a fixed offset (default UTC) |
| Time | `to_timestamp` | `tz`? | a `datetime` → epoch seconds; a naive value is read at `tz` (default UTC, never the machine's zone) |
| Time | `sleep` | seconds | block for that many seconds and return the upstream value unchanged (the allowlist's only blocking action) |
| Conversion | `str` / `int` / `float` / `bool` | — | type conversion (`bool` follows Python: `"false"` is true); failure is `UP2-E2005` |
| Conversion | `items` | — | a dict → `[[key, value], …]` |
| Conversion | `from_json` | — | JSON text → JSON tree |
| Predicate | `==` / `!=` / `<` / `<=` / `>` / `>=` | `to` | comparison; ordering takes two numbers or two strings, otherwise `UP2-E2002` |
| Predicate | `in` | `container` | Python's `in`: the parameter is the container |
| Predicate | `between` | `[lo, hi]` | `lo <= value < hi`, numbers only, half-open |
| Predicate | `or` / `and` | operand array | Python's `or`/`and` over `[value, *operands]`; an empty array answers the upstream value |

**Time is Python's pair on real values.** `strptime` produces a `datetime`, `strftime` consumes one, and `from_timestamp` / `to_timestamp` convert epoch
seconds. A `datetime` may flow between stages (the value model allows host objects) but it is **not exportable**: the exit reports `UP2-E2003` and names
`py.strftime` as the way out. There is no format guessing: the format is explicit and validated at compile time, so `03/04/2026` needs `"%d/%m/%Y"` or
`"%m/%d/%Y"`. Relative and natural-language dates are out of scope (a host `udf` or `code`). The layout allowlist is locale-free and platform-stable: `%a` /
`%A` / `%b` / `%B` / `%p` / `%c` / `%x` / `%X` are locale-decided, `%Z` is platform-decided, `%e` / `%k` / `%l` / `%G` / `%V` are platform-specific and `%s`
would assume a zone, so each is `UP2-E1005` at compile time. `%z` is allowed.

**Side by side with `udf` / `code`** (trust levels):

| Operator | Where the code lives | Action space | Auditability |
|---|---|---|---|
| `py` | in the engine, already audited | **closed** (48 named functions) | "this chain can do at most these 48 things" |
| `udf` | in the host, invisible to the chain | **open** (whatever the host registers) | deployment-bound |
| `code` | **in the chain itself** | a **single** behaviour | visible in the chain itself |

### 6.5 `py.const` — literal

`["py","const", <arbitrary JSON value>]`. Used for fixed source identifiers (`channel` / `source` / `region`, see `03` §8.1) and for any constant a chain needs.
The former `const` operator is gone (D0): a literal is an action of the `py` table, so there is one fewer operator and the stage shape stays uniform. **The
structure is not copied** (it is treated as immutable and must not be modified in place at runtime).

### 6.6 ~~`cast`~~ — merged into `py`

**This section is obsolete** (D-02-14): type conversion no longer has an operator of its own; it becomes the six `py` functions `str` / `int` / `float` / `bool`
/ `list` / `from_json`, see §6.4. The reasons:

- they are Python builtins to begin with, and turning them into an operator would only drag in another set of slot conventions about "which position holds the
  target type";
- `["cast", "int"]` and `["py","int"]` have exactly the same expressive power, and one operator fewer means one document fewer and one conformance
  declaration fewer;
- **`datetime` is an internal value only**: `strptime` / `from_timestamp` produce one, `strftime` / `to_timestamp` consume one, and the exit refuses it
  (`UP2-E2003`); it never enters the stored JSON value domain;
- when the business side wants `str`, it writes `"str"` in the business schema instead of relying on a forced conversion at the end of the chain.

### 6.7 ~~`time`~~ — absorbed into `py`'s `strptime` / `strftime`

**This section is obsolete**: time parsing no longer has an operator of its own, and it no longer guesses a format. It is Python's pair on real `datetime`
values inside the chain:

```jsonc
["py", "strptime", "%Y-%m-%d %H:%M:%S"]   // text + explicit format -> datetime
["py", "strftime", "%Y/%m/%d"]            // datetime + layout -> text
["py", "from_timestamp", 8]               // epoch seconds -> aware datetime at +08:00
["py", "to_timestamp"]                    // datetime -> epoch seconds
```

- `parse_time`, its built-in format table, `lang` / `date_order` / `now`, the `[time]` extra and `UP2-E2007` / `UP2-E2008` are all deleted: an action that
  guesses a shape, or reads the wall clock, makes the same chain answer differently on different days, and `dateparser` was its only dependency.
- A text that does not match the explicit format is `UP2-E2005`, naming the format. Ambiguous writings must name their order in the format
  (`"%d/%m/%Y"` / `"%m/%d/%Y"`), and relative / natural-language dates go to a host `udf` or to `code`.
- A zone in the text (`Z`, `+0800`, `%z`) is kept on the value when the format parses it; `strftime` renders it only when the layout asks for `%z`.

### 6.8 `ctx` — scope reads and writes

| Action | Value kind | Semantics |
|---|---|---|
| `get` | `literal` (bare path text) | read a scope path |
| `set` | `literal`, **the path must start with `locals.` or `public.`** | write the upstream value into the locals or the run's public scope |
| `del` | `literal`, **the path must start with `locals.` or `public.`** | delete a local or a public value |
| `dict` | `literal`: a "name → bare path" object | batch read → an object |
| `list` | `literal`: an array of bare paths | batch read → a list (a `*args` payload) |

> **Paths are always written as bare path literals** (`locals._tmp` / `globals.base_url`), **without a `$` and without a `ctx.` prefix**. This was converged
> while implementing L1: the `04` draft mixed the two spellings (`["ctx","get","ctx.locals._raw"]` versus `["ctx","map",["locals.a.b"]]`), whereas the target
> position of `set`/`del` **does not exist yet** and could never have been handed to the reference evaluator to read — once the paths are unified as literals,
> all four actions are written the same way, and the reference `$locals.x` (used in other operators' parameter slots) keeps its semantics unchanged: the two
> read the same value, only the entry point differs.

> **Ruling (tightening §2.8 of the `04` draft and blocker U of the `02` worked example)**: the `04` draft offers four actions `get/set/del/map`, and Q41 of `01`
> proposes the three verbs "read / assign / call a function", but the **write-permission boundary and the write-back timing were never defined** (blocker U of
> the `02` worked-example draft says so explicitly). This design **hard-limits the write surface to `locals.*` and `public.*`**: `ctx.set` writing `globals.*` or a node
> product ⇒ compile-time `UP2-E1015`. Reasons: (a) if `globals` could be changed, the same value would differ depending on when a field is evaluated, and the
> purity of `N1` would fail; (b) if node products could be changed, a "node product" would no longer be an immutable snapshot and downstream references would
> read intermediate state. `public` is the third scope (`03` §8): the **run's** own notes, writable and readable from any node, and **not** chain data — it
> never enters the fingerprint, so writing it cannot break "same chain, same result". `call` is no longer a `ctx` action — calling a function is the operator itself (`py` / `udf`) and does not need a third entry point.
>
> **The relationship between the two spellings**: `["ctx","get","locals._raw"]` (a stage) and the reference `$locals._raw` (a parameter slot) read the same
> value in the same scope. The former is used to "switch the input source in the middle of a chain", the latter to "pass some value to an operator as an
> argument". Neither introduces a new scope concept.

### 6.9 `each` — one pass per element of a list

```jsonc
["each", {"title": [["css1","text","a"]], "href": [["css1","@href","a"]]}]   // one dictionary per element
["each", [["py","strip"]]]                                                  // one value per element
```

`each` is a 2-slot operator with a single action, so slot 2 carries the whole argument. **The argument's shape selects the mode** (D8): an **object** is a
field map (exactly the shape a node's field map has, `03` §7, one level down); an **array** is one chain run over every element, answering a list of its
products. Anything else is `UP2-E1005`.

| Argument | Result |
|---|---|
| an object of field name → chain, compiled recursively | `list[dict]`, one dictionary per element |
| one chain | `list`, one product per element |

- **The input must be a list**: one product per element, in input order. An empty list yields `[]` (not a missing value); anything that is not a list reports
  `UP2-E2002`. A missing input keeps the shared short-circuit (the operator does not accept a missing value).
- **Every field chain starts from the element**: the element is the first stage's input (the current element is a value, not a named root).
- **Fields are evaluated in declaration order against one element at a time**, so a later field reads what an earlier field of the same element stored.
- **A `_`-prefixed field name is a per-element local**: it never becomes a key of the element's dictionary, and later fields of the same element read it as
  `$locals._name` (or with `ctx.get`). `ctx.set "locals.x"` mid-chain writes there too.
- **Every element is evaluated in its own child scope**: a read falls back outward **by name** — the element's locals, then the calling scope's, then the
  chain-level values — so a name the element itself wrote is resolved there and nowhere else: `$locals._a.b` is a miss when the element's own `_a` has no `b`,
  even if the calling scope's `_a` does. Writes always land in the element's scope, and the element's locals do not outlive the element.
- **A missing field is simply not part of the element**, and no element is ever dropped: an element whose fields all resolve to absent is still `{}`. A `Failed`
  propagates out of `each` with the failing stage's code.
- **Limits**: nesting deeper than `MAX_EACH_DEPTH` (3) is `UP2-E1012` at compile time; a list longer than `MAX_EACH_ITER` (10 000) is `UP2-E2012` before
  anything is evaluated (`01` §9); a field map with more than `MAX_FIELDS_PER_MAP` (256) fields is `UP2-E1012` at compile time, and an empty map — or a field
  name that is empty or contains `.` — is `UP2-E1005`, because no reference path could address such a key.

> **Deviation record D-02-4** (superseded by the L2 iteration redesign, change `l2-chain-structure-and-each`): the `04` draft encoded the selector as the string
> `"ctx.fields._rows|each"`, used a `ctx.` prefix outside `"$"`, and called the chain container `parsers`; the design at that time answered with an object-form
> selector plus a `presets` container, and a node-level `select` for the fan-out. Both are retired: one operator, one inline field map, and the input comes from
> the stage above. See `design.md` D1–D3 of that change for the measurements behind it.

### 6.10 `udf` — a host-registered named function

```jsonc
["udf", "ah_normalize_title"]          // f(value): the upstream value is one DTO argument
["udf", "fetch", "*"]                  // f(*value): the upstream value is a list
["udf", "fetch", "**"]                 // f(**value): the upstream value is a mapping
["udf", "translate", "en"]             // f("en"): one explicit argument
```

- The function resolves from the **run's udf table**: `register_udf(name, fn)` installs process-wide defaults, and
  `run(story, …, udfs={"fetch": my_fetch})` overlays them for that run. A name the chosen node uses
  (directly or through a call) but the table lacks is
  `UP2-E1010`, reported by `run` **before** evaluation with the names that are available.
- **Four argument forms** (the third slot selects the call):
  - omitted ⇒ `f(value)`, the upstream value as one DTO argument;
  - the literal `"*"` ⇒ `f(*value)`, the upstream value must be a list;
  - the literal `"**"` ⇒ `f(**value)`, the upstream value must be a mapping with string keys;
  - any other value ⇒ `f(argument)`, the resolved literal/reference as the single argument.
- The signature is checked at compile time **when the function is already in the table**; an unknown name is
  deferred to `run`'s pre-flight, because the table is run state. A function that cannot accept the selected form
  is `UP2-E1005` at compile time when known.
- **A udf may answer any value.** A host object (a response, a node handle) is carried by reference and read with
  `py.getattr`; only the run's exit (`UP2-E2003`) requires JSON. An awaitable answer is
  `UP2-E2009`: the kernel is synchronous, so the host calls an async function in its own event loop before returning.
- **`ctx` is not injected**: a function that needs the scope takes the payload the chain hands it; writing the scope
  stays `ctx.set`'s job.
- **The action space is dynamic**: `udf`'s "action" is the function name (slot 2), so `up2 conformance` declares it
  as **`("udf", "*")`**.
- **Security boundary**: the chain carries no code; it can only name functions the host reviewed and registered.
  This is the replacement for the old v3 `udf` (arbitrary source through `exec`/`eval`).

Registration is trust: `udf` functions run with the host's full authority, so "what a chain can do" is what this
deployment registered; scope and trust boundaries are in `04` §11.

### 6.11 `xpath` — XPath query (XML)

**Slots**: `["xpath", accessor, XPath expression]` — the accessor is in position 2 and the expression in position 3. A namespace map makes the expression
a two-element array `[expression, ns]` (D3).

```jsonc
["xpath", "text", "//item/title"]
["xpath", "text", ["//dc:creator", {"dc": "http://purl.org/dc/elements/1.1/"}]]
```

| Accessor | Expression kind | Product | Notes |
|---|---|---|---|
| `text` | expr + ns (both literal) | `list` | for elements, **all descendant text** (`itertext`); attribute/string/number results pass through unchanged (`//enclosure/@url` → a list of strings) |
| `nodes` | as above | `list[Opaque]` | handles of the matching nodes; a non-node mixed into the result ⇒ `UP2-E2002` (the hint suggests switching to `text`) |
| `self` | as above | `Opaque` | the first matching node, after which `./` / `.//` **relative paths** can be used to continue selecting |

- **Why XML uses XPath rather than CSS** (measured): selectolax raises `ValueError: Bad CSS Selectors` outright for `dc|creator`, `dc\:creator` yields `[]`, and
  it merges `<Item>` with `<item>`; in XPath, `//dc:creator` plus one mapping is correct, and CDATA, case sensitivity and self-closing tags are all natively
  correct.
- **There is no `@<attribute name>` accessor**: XPath can take attributes by itself (`//enclosure/@url` returns a list of strings), which is where it beats CSS.
- **There is no "take only the first" sibling operator**: the reasons are in D-02-11 in §6.1 (for a scalar, explicitly append `py.first`). **Note that this is a
  deliberate asymmetry**: the `css` side has `css1` (both cardinalities explicit) while the `xpath` side has only the full-cardinality form. The reason is that
  XPath has no measured need for "take the first" yet, and lxml has no `css_first`-style single-selection entry point (the gain would likewise be only in the
  value-extraction phase). If that need ever does appear, adding an `xpath1` reuses the same `first_only` flag and changes no semantics.
- **Default namespaces are a silent trap**: in `<urlset xmlns="…">` (which is what a sitemap is), `//loc` **returns empty without raising**. The empty
  result is the shape's empty value (`[]` / `None`), so the fix lives in the chain: `//*[local-name()='loc']` (no configuration needed) or a prefix in the
  `ns` mapping.
- **Undefined prefixes**: when `//dc:creator` is given without `ns`, lxml raises `XPathEvalError: Undefined namespace prefix`. Measured, that error appears
  **only at evaluation time** (the construction phase does not raise), so at compile time the engine **tries one run** against an empty document, pulling
  prefix/function-name errors — which do not depend on the document — forward to compile time (`UP2-E1005`, in keeping with "bad chains fail at compile time").
- The input is a `str` (XML text) or a node (`XPathNode`); **the XML must be well formed**: a parse failure ⇒ `UP2-E2005`, and the fix points straight at the
  `css` operator (use it for HTML).
- There is only one dependency: **`lxml`** (`requires=("lxml",)`) — no `cssselect`, no bs4; XPath is native lxml capability.
- Nodes are wrapped as `XPathNode(Opaque)` and are likewise rejected at the exit (`UP2-E2003`).

### 6.12 `code` — code inside the chain (sandbox)

**Slots**: `["code", <source>]` — 2 elements, and the source **is** the parameter (D9). `src` must be a non-empty string: missing ⇒ `UP2-E1005`; a
whitespace-only string is likewise `UP2-E1005`. There is no `inputs` parameter and no third slot (`UP2-E1004`).

```jsonc
["code", "len(obj)"]                         // minimal form: obj and the allowlisted functions
["code", "ctx.locals.n + 1"]                 // read this scope's temporary variable (locals.n = 41 ⇒ 42)
["code", "ctx.globals.base_url"]             // read the chain-level environment
["code", "1 / 0"]                            // an exception ⇒ UP2-E2017
```

**Return-value semantics: the value of the last expression is the return value** (REPL semantics). If the end is an assignment, a pure comment or an empty
string ⇒ `None`; `x = 1 + 1; x * 3` ⇒ `6`. **`print` is silenced** (the host passes a no-op `print_callback`): the product is the channel, not stdout.

**Fixed names `obj` and `ctx`**: `obj` = the upstream value; `ctx` = the **scope object** (not a JSON dict), read attribute-wise (`ctx.locals.x` /
`ctx.globals.y`). A missing attribute is an observable failure (`AttributeError` ⇒ `UP2-E2017`). Configuration goes through a payload built with `ctx`, the
same pattern `udf` uses.

**`ctx` contains JSON values only**: handles (DOM / XPath nodes) do not appear in `ctx`, and no error is raised because of their absence — the same principle
as `UP2-E2003`. When the upstream value itself is a handle it is rejected explicitly (`UP2-E2003`).

**Assignments to `ctx` inside the sandbox do not flow back** to the engine scope: to write, use `ctx.set` in the chain.

```jsonc
[["code", "len(obj)"], ["ctx", "set", "locals._n"]]
```

**Allowlisted functions are directly available**: the sandbox namespace is preloaded with the same pure functions as `py`, so a fragment can write
`normalize_space(obj)` without `import`; actions with an incomplete dependency (such as `html_to_markdown`) are not mounted. Each call is one host round-trip,
bounded by the budget (default 1000; `0` makes them uncallable). When `json` / `re` / `math` / `base64` / `datetime` / `collections` / `itertools` /
`functools` / `unicodedata` are needed, the sandbox can `import` them (a stdlib subset).

**`UP2_CODE=off` disables the operator** before any sandbox work (compile-time `UP2-E1107`); the environment variable is the deployment's switch, convenient
for containers.

**Isolation and limits**:

- **No host capability, stated per surface as measured**: `import socket` / `import subprocess` do not exist in the sandbox VM (`ModuleNotFoundError`), and
  neither do `compile` / `__import__`; `open(…)` and `os.getenv(…)` exist and are blocked at runtime (`PermissionError` / "not supported in this environment"),
  from the Monty runtime defaults, see `04` §11.3; `eval` / `exec` exist but grant no capability; `time.sleep` is neutralised. The classic escape chain
  (`''.__class__.__mro__[1].__subclasses__()`) fails at the language level (`AttributeError`) and lands on `UP2-E2017`.
- **The limits live on the host side only** (`uniparser2.ops.code.configure`): memory (default 64 MB), single-execution duration (0.5 s), request timeout (5 s),
  host round-trip budget (1000), recursion depth. **They cannot be changed from the chain** — there is no parameter slot to pass them through.
- **Deterministic by default**: a frozen clock + a fixed time zone + `sleep` disabled + seeded random, so the same chain with the same input replays
  character for character; the host may explicitly switch back, giving up the cross-machine replay guarantee.
- **An optional extra, `uniparser2[code]`** (`pydantic-monty`): absent by default; when missing, compile-time `UP2-E1107` + the install command, and `up2 ops`
  marks it unavailable; `uniparser2[all]` does not include it.

**Error codes**: a limit ⇒ `UP2-E2016`; an exception in the sandboxed code ⇒ `UP2-E2017`; a non-product return (or a non-JSON input) ⇒ `UP2-E2009`; an upstream
handle ⇒ `UP2-E2003`.

### 6.13 `node` — call a story node

```jsonc
["node", "detail"]          // run node `detail` with the current value as its `$in`
```

`node` is a **composition** operator: two slots, the node name in slot 2. It has one action (`call`), so the stage
never writes an action slot. The current stage value becomes the callee's `$in`; the callee's product becomes the
stage value. The call shares the caller's `$locals` and `$public`, and the caller's `$in` is restored on return.

- The name MUST be a literal naming a node of the same story; an unknown name is `UP2-E1016` at compile time,
  listing the node names.
- The node-call graph MUST be acyclic; a cycle is `UP2-E1017` at compile time, with the travel path and the stage
  that closes it.
- A `node` stage is only valid inside a story: a standalone chain compiled with no node table rejects it with the
  same `UP2-E1016`.
- A three-slot `["node", name, …]` is `UP2-E1004`: the call has no argument slot. Put a stage in front of it to
  produce a different input.

### 6.14 `type` — validate a chain's product

```jsonc
["type", "Article"]         // build the registered `Article` from the value, carry it on
```

`type` is an ordinary **constructor** operator: two slots, the type name in slot 2, one action (`check`). It applies
the host's type registry at this stage:

- a mapping ⇒ `Cls(**payload)`, a list ⇒ `Cls(*items)`, anything else ⇒ `Cls(value)`;
- the constructor **is** the constructor: whatever it answers is what the chain carries on, so a container type
  carries a host object that a later stage reads with `py.getattr` or hands to a `udf`;
- the stage may appear **anywhere** in a chain (`chain-tail` was the rule until the value really flowed);
- an unregistered name is `UP2-E1011`, listing the registered names; a constructor that raises is `UP2-E2019`,
  with its own exception text;
- a constructed value at the run's **exit** is `UP2-E2003`, because the exit is JSON;
- a run may inject its own table: `run(story, types={...})` (a name → constructor map, or a sequence of classes
  named by `__name__`), the same overlay pattern `udfs={...}` uses.

A pydantic model needs no special case — `Model(**payload)` is the same contract. A `TypedDict` is **not** a type:
at runtime it erases to `dict` and validates nothing. `NamedTuple` works with no special case.

## 7. Compile-time error codes (`UP2-E1xxx`)

Every code must satisfy: unique, stable, carrying a one-sentence fix, and enumerating the available values.

| Code | Trigger | Fix hint |
|---|---|---|
| `UP2-E1001` | unknown operator | list the operator names available in the registry (including aliases) |
| `UP2-E1002` | unknown/reserved action | list all legal actions of that operator |
| `UP2-E1003` | the `py` function is not in the allowlist | list the allowlisted function names |
| `UP2-E1004` | stage length/arity mismatch | give the legal forms of that operator |
| `UP2-E1005` | parameter Schema validation failure (type/required/unknown parameter) | give the parameter name + the expected type + the actual type |
| `UP2-E1006` | the reference names an unknown root, or reads a path the compiler can prove wrong | give the available roots |
| `UP2-E1007` | a literal was written in a `ref` position | hint that the position must be a `$…` reference |
| `UP2-E1009` | a node name is a reserved root (`globals`/`locals`/`public`/`in`/`obj`), contains `.` / `/` / `~`, or is duplicated | list the reserved roots and the declared node names (`03` §2.1) |
| `UP2-E1010` | a `udf` name is not in the run's table | name the missing function and the available ones; register it with `register_udf` or `run(udfs={...})` |
| `UP2-E1011` | a `["type", name]` stage names an unregistered type (checked when the stage runs, `03` §3.3) | list the registered type names (`03` §3) |
| `UP2-E1012` | a resource limit is exceeded (`01` §9) | give the constant name that was hit and the limit value |
| `UP2-E1013` | the regex contains a nested quantifier (ReDoS risk) | hint at rewriting it or switching to non-greedy |

**The codes retired while implementing L1 (the reasons are recorded so that they are not "added back" later)**:

| Retired | Reason |
|---|---|
| `UP2-E1008` "a reference was written in a `literal` position" | it conflicts with §3.2: a `$` in a `literal` position **is always a literal** (that is exactly the point of deciding by kind), so this error cannot occur. An extra code is an extra branch |
| `UP2-E2006` "regex execution timed out" | **there is no real mechanism**: Python's `re` has no `timeout` parameter (measured on 3.13/3.14). Better to delete the code than to keep a false promise |
| `UP2-E2015` "the effective policy would raise on a missing value" | the settlement policy is **retired** (`01` `D-01-1`), and the third outcome was removed later (`empty-value-semantics`): absence is the shape's empty value (`01` §4.2). The number is not reused |

**The current status of `UP2-E1007`**: L1's operators (`const`/`re`/`py`/`ctx`/`each`) **have no `ref`-only parameter** — `ctx`'s path is literal path text,
`each`'s field map is a structured parameter and `py`'s parameters are `ref_or_literal`. `ctx`'s `refs` parameter keeps the rule alive at compile time, and L1 covers
it with a test patched to "temporarily turn `urljoin.base` into `Kind.REF`".

> A runtime failure is returned as `Failed` with the code of the stage that failed; it always fails the run (there is no
> policy that degrades it into a value), and the node/field location of that stage goes to the trace (`01` §10).

## 8. Summary of differences from the `04` parser-syntax draft (the internal source material, not shipped in this repository)

| # | `04` draft wording | This design | Reason |
|---|---|---|---|
| D-02-1 | `const`/`cast` are 2-element, the rest are 3-element | the arity is declared by the operator Schema (2 or 3) and the stage length is **matched exactly**; there is no "omitting the tail" | the shape is unified; the arity is a property of the operator and should not be hard-coded in a document |
| D-02-2 | multiple arguments passed as a comma-joined string (`"old,new"`) | one positional array (`["old","new"]`) | string joining cannot be validated or escaped, and `essence` already lists it as the R1 root cause |
| D-02-3 | `remove` is a side effect | `remove` returns a pruned copy (a pure function) | preserves `N1`/I5; avoids the cross-talk of a shared mutable DOM during per-item parsing |
| D-02-4 | `callback` uses a `"ctx.fields.x\|each"` string; the preset-chain container is called `parsers` | **superseded** by the L2 iteration redesign (`each`): the argument is an inline field map, so there is no selector object, no container and no name to resolve | no string surgery, one shape in one slot, and the terminology does not collide |
| D-02-5 | `ctx` has `get/set/del/map` with an undefined write surface; there is also a `call` verb | the write surface is hard-limited to `locals.*`; `call` is deleted | preserves purity and the immutability of products; calling a function is an operator |
| D-02-6 | three reference forms are undefined (`$locals.*`, multi-level paths, literals), and an undefined `$get` appears | one rule: a leading `$` ⇒ a reference, `{"$lit":…}` escapes; `$get` is abolished | a rule must fit in one sentence; undefined concepts are deleted |
| D-02-7 | the `cast` vocabulary contains `datetime`, which conflicts with exit encoding (blocker N of the `02` worked-example draft) | `strptime` / `from_timestamp` produce a `datetime` that may flow between stages but is refused at the exit (`UP2-E2003` names `py.strftime`) | the stored value domain is a JSON tree; a datetime is an internal value only |
| D-02-8 | the `py` table contains `const`/`getattr` (as well as `int`/`float`/`bool`/`str`/`list`) | `const` is a standalone operator; `getattr` **came back** with host objects (`allow-object-values`), where it reads an attribute of the value that flows in and refuses a callable one; the five type functions first went to `cast` and then, with D-02-14, back to `py` | a single entry point, avoiding one name meaning two things |
| D-02-9 | the `re` capture-group action does not say how pattern and group name are given together | `search` takes `[pattern, group]`; the separate `group` action is gone | one action fewer, and two parameters fit one positional array |
| D-02-10 | there are no `default` / `first` / `sort` / `uniq` / `urlsplit` / encoding functions | the allowlist functions are completed | the list was ported from `dsl-design` §3.4 and taken from `essence` §3.4; these are equivalent ports of existing behaviour |
| D-02-11 | `css1` was deleted for a while (replaced by `css` + `py.first`) | `css1` is restored: `css` produces a `list`, `css1` produces a scalar | in L1 `nodes` cannot shoulder "take all values"; first-match-by-default risks silent truncation; `css_first` is not a fast path and the gain is in extracting N-1 fewer values |
| D-02-12 | `css` chooses between `selectolax` / `beautifulsoup4` (`any_requires`) | only `selectolax` remains; XML goes to `xpath` (lxml) | measured, the two engines have identical HTML semantics; `any_requires` had a single user |
| D-02-13 | the slot-order dispute: the `04` draft's "slot 2 is always the action" versus the old draft's "selector first" | the slot order is unified with **zero exceptions** as `[operator, action, parameter]` — the css/xpath selector lands in slot 3, and `json`/`const` are written with two positions | the enumeration strength of the three positions increases step by step (operator → action → arbitrary value); the interim "selector first" flip was withdrawn because of the tax of two shapes (`action_slot` declarations, two pointer shapes) |
| D-02-14 | `time` / `cast` each occupy an operator; action names carry `$`; `re`'s actions are called `$match` / `$all` | both are merged into `py` (`strptime`·`strftime` / `str`·`int`·`float`·`bool`·`from_json`); all `$` are removed; they are renamed `search` / `findall` | a single behaviour does not need an operator of its own; `$` is easily confused with the reference syntax; `match` conflicts semantically with `re.match` |
