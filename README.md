# uniparser2

[English](README.md) | [Chinese (zh-CN)](README.zh-CN.md)

A declarative, deterministic, serializable **text parsing engine**: it turns the process of going from
input text to a specified structure into JSON data (a **parse chain**), generated offline by a human
or an LLM, with nothing but deterministic evaluation at runtime.

> **Status**: `0.5.0`. **L1** (the DSL operator layer) is complete: **10 operators** —
> `css` / `css1` (HTML selectors — all matches vs. first match only, selectolax), `xpath` (XML, lxml),
> `json` (jmespath), `re`, `py` (46 allowlist functions), `udf` (host-registered, no code in the
> chain), `code` (in-chain code, language-level sandbox, **not present by default** — see the
> security note), plus the scoping operator `ctx` and the iteration
> operator `each` — 77 `(operator, action)` pairs in total. **L2 has started**: a site bundle (a
> **story**) compiles and runs — `start(bundle, value)` / `run.go()` / `run.feed(answer)`, where a
> `Request` / `RequestBatch` / `call` suspends the run and its answer resumes the **same** run — and
> both `samples/*/site.json` run end to end against their live sites through the committed host
> recipes (`samples/*/host.py`, which register the samples' own domain types with `register_type` and
> take the seed URL from the command line). The fetching is the package's own default
> (`uniparser2.net`): a synchronous, standard-library downloader plus a request cache under
> `.cache/requests/`, so a second run replays the answers instead of the network. A bundle declares
> **both endpoints**: `entry` names the
> step the run starts at and `collect` the step whose products leave, and a step nothing reaches is
> `UP2-E1018` at compile time. A chain may also be a **reference** (`"url": "$in"`), which is how
> identity is written — the identity stage `py.id` is gone.
> Try one from the CLI: `uv run up2 lint samples/books.toscrape.com/books/site.json`, and the full
> run with `uv run python samples/books.toscrape.com/host.py`. The **type registry** has landed too:
> a host registers a name → constructor with `register_type(name, constructor)`, and the kernel builds
> it from the product at the step boundary, so a declared shape is validated where the product is made.
> The run-scoped **materialization cache** has landed as well (`MAX_MATERIALIZE_BYTES` / `MAX_MATERIALIZE_ITEMS`,
> LRU): one document is parsed once per run, however many fields read it. **L3 has started**: the
> **template store** (`04` §1–§6) binds a chain to a `(root_domain, tpl_key)` identity — one row per
> chain, a `blake2s` fingerprint, an append-only audit, and two implementations behind one
> `TemplateStore` protocol (a file store and SQLite) — with `up2 publish` / `get` / `audit` over it,
> and the **SOP commands around it**: `up2 snapshot` freezes a case's product, `up2 test` regresses the
> frozen chain over every sample (a mismatch prints a JSON Pointer difference), `publish` regresses that
> set before it writes, and `up2 doctor --fix` repairs a chain that has no audit row. The `S0–S7`
> walkthrough of `04` §7 is runnable from S2 on, and `up2 trial --trace` reports a run's per-stage
> trace (`06` §5.1). `up2 list` and the in-place trial UI are not there yet. For progress and
> acceptance criteria see the roadmap in the design notes; to
> see the operator layer run right now, in a source checkout: `uv run python demo.py`. (`demo.py` and
> `tools/demo_report.py` live in the repository only: neither the wheel nor the sdist ships them.)

## Why it exists

People writing scrapers or extraction rules keep running into the same set of problems: the rules are
scattered through code, changing one of them means shipping a release, a failure does not tell you
which step came up empty, there is no safe way to let an LLM generate rules, and there is no way to
store rules as data and reuse them. uniparser2 solves all five at once:

| Principle | What it means |
|---|---|
| **The chain is data** | A parse chain is a JSON array: it can live in a file, in a database, in a diff, or be generated by an LLM; serialization is a **character-for-character stable** fixed point |
| **Pure functions, zero IO** | Same input, same chain → same output; the kernel opens no network connections, reads no files and uses no coroutines, so chains can be replayed, snapshot-regression tested and run in CI |
| **A single boxing point at the exit** | Every value leaving a chain passes through the same function: DOM handles and other non-serializable values are rejected there, so chain behavior cannot leak through a seam |
| **A no-match is a value, not an error** | One outcome carries values and one carries failures: a query that matches nothing answers the shape's empty value (`""` / `[]` / `null`), so an optional field does not blow up the chain, while a bad rule is stopped at **compile time** |
| **No code capability inside rules** | A rule reaches no host capability: no third-party import, no file, no network, no process. Custom logic can only enter through named host-registered functions (`udf`), which keeps the extension surface controllable. The only exception is the **optional** `code` sandbox — neither the default install nor `uniparser2[all]` includes it (see the security note below) |
| **Dependencies are optional per operator** | The kernel has zero third-party dependencies; every operator (even every action) declares its own, and a missing one only makes that action unavailable, printing the install command |

## What you get today (L1)

The **operator layer** is complete and mechanically audited: 10 operators, 77 `(operator, action)`
pairs, each with a covering case (`uv run up2 conformance --check`), and 35 implemented error codes
each asserted by a test. The **store** (L3's first slice) has landed on top of it: `up2 publish` binds
a chain to a `(root_domain, tpl_key)` identity, refuses a chain that does not lint, keeps its
fingerprint history append-only, and `up2 get` / `up2 audit` read it back — over a file store or a
SQLite one (`UP2_HOME`, `UP2_STORE`).

| Operator | Engine (extra) | Actions |
|---|---|---|
| `css` / `css1` | selectolax (`[html]`) | `text` · `html` · `outer` · `@<attr>` · `remove` · `self` · `nodes` — all matches vs. first match only |
| `xpath` | lxml (`[xml]`) | `text` · `self` · `nodes` (XML; XPath is lxml-native) |
| `json` | jmespath (`[json]`) | `get` — a jmespath expression; omitting the third slot queries the whole document |
| `re` | stdlib | `search` · `findall` · `sub` — `search` takes a pattern or `[pattern, group]` |
| `py` | stdlib; `html_to_markdown` needs `[md]` | 46 allowlisted pure functions: `const` `strip` `normalize_space` `html_to_markdown` · `replace` `split` `join` `upper` `lower` `slice` `getitem` `getattr` · `len` `first` `last` `flatten` `uniq` `sort` `sort_desc` `find_jsons` · `items` · `urljoin` `urlsplit` · `strptime` `strftime` `from_timestamp` `to_timestamp` · `b64_encode` `b64_decode` `sha256` `md5` · `str` `int` `float` `bool` `from_json` · `==` `!=` `<` `<=` `>` `>=` `in` `between` `or` `and` (predicates, Python's spellings) |
| `ctx` | stdlib | `get` · `set` · `del` · `dict` · `list` (scope reads and writes; `obj` names the stage's value) |
| `udf` | host-registered | any function the host registered beforehand; the chain carries only a name, and the call is unary or nullary |
| `code` | pydantic-monty (`[code]`, deliberately not in `[all]`) | `run` — in-chain code in a language-level sandbox, written `["code", src]` (see the security note) |
| `each` | stdlib | per element of a list: an **object** parameter is a field map (one dictionary per element), an **array** parameter is one chain run over every element |

This table is a summary: **the registry is the authority**, so ask it. `uv run up2 ops --json` prints
every operator with its arity, slot roles, action enumeration, parameter schema, dependencies,
availability and install hint — that output is also what to feed an LLM before asking it to write a
chain.

## Not there yet (L2–L4)

The operator layer is complete and a **first story executor** exists, with the type registry and the
run-scoped materialization cache behind it, and the **template store** (`04` §1–§6) has landed: the
`Template` / `template_audit` records, the `blake2s` fingerprint, the `TemplateStore` protocol with
`FileStore` and `SqliteStore`, the `publish` gates and `up2 publish` / `get` / `audit`, plus the SOP
commands `up2 snapshot` / `test` / `doctor` and the committed sample case `samples/local/demo/`. The
rest of the design's L2/L3 is unimplemented: no `up2 studio` bench and no
`up2 list` (the `TemplateStore.list` method exists, no command prints it); the ADRs have not been
written either. There are no `seed` / `body` /
`emit` node types and no `routes` — that model was retired with the story model, so what is left to
build is the list above.
The CLI is exactly `ops` / `conformance` / `lint` / `trial` / `snapshot` / `test` / `publish` / `get` /
`audit` / `doctor`, and the
public API is `compile_field` /
`compile_stage` / `compile_story` / `start` / `eval_field` plus the value, scope and trace types
(`Trace` / `TraceEvent`, what `up2 trial --trace` reports; the store is
its own layer, `uniparser2.store`). The layers,
their deliverables and their acceptance criteria are in
[`docs/specs/007` §3](docs/specs/007-source-decisions-and-roadmap.md).

## Installation

```bash
# Kernel only (zero dependencies)
uv add uniparser2

# Install engines as needed: HTML parsing / XML / JSON queries / HTML→Markdown
# (`ui` is the trial bench, not implemented yet, and — like `code` — deliberately not part of `[all]`)
uv add "uniparser2[html]"
uv add "uniparser2[all]"

# Sandboxed execution of in-chain code (not installed by default, and [all] does not include it either —
# installing everything should not hand out code execution as a side effect)
uv add "uniparser2[code]"
```

Python ≥ 3.12 is required. The kernel depends on no third-party package; extras such as
`uniparser2[html]` are what bring in the engines.

**Security note**: a default install (including `uniparser2[all]`) **carries no code execution
capability** — a chain can only call the operators and actions already declared in the registry. Both
ways of giving a chain custom logic must be enabled explicitly by the host: `udf` can only reference
named functions the host registered beforehand (the chain holds nothing but names), while `code` puts
a piece of code into the chain and runs it inside a language-level sandbox (measured: no third-party
import, no network, no process, and no reachable host file or environment — which of those surfaces is
*absent* and which is *blocked* is listed surface by surface in
[`docs/specs/004` §11.3](docs/specs/004-persistence-and-sop.md)), and it exists only once
`uniparser2[code]` is installed —
without it, it fails at compile time with `UP2-E1107`. **Whichever of the two paths was taken is
greppable in the chain's frozen artifact** (search for the operator names `udf` / `code`); there is no
need to go back to the host code.

Be precise about what that sandbox is: it is **language-level, not OS-level isolation**. The VM gives
sandboxed code no host capability to reach; where a surface is merely *blocked* rather than absent
(`open`, `os.getenv`), the rejection is the upstream runtime's default rather than a boundary this
project configures. The language features `eval` / `exec` do exist inside the sandbox and carry no
capability by themselves. It is not a boundary around the process, and time and memory are bounded
only by the limits the host configures (64 MB and 0.5 s per evaluation by default).

## Quick start

Start by asking the command line what operators, actions and parameters exist — **this is step one
before writing a chain**:

```bash
uv run up2 ops                      # human-readable: operators / actions / arity / slot roles / availability
uv run up2 ops --json               # machine-readable: feed this to an LLM before asking it to generate a chain
```

Write a chain (one field chain = an array of chain steps); this one takes the four-digit year out of a
publication-date text:

```jsonc
// chain.json
[
  ["re", "search", ["(\\d{4})-(\\d{2})", 1]],
  ["ctx", "set", "locals._year"],
  ["py","int"],
  ["py","or",[0]]
]
```

A stage that may fail can be guarded by the step before it — `["try","skip"]` keeps the value the
chain carried and carries on, `["try","break"]` ends the chain with it, and a guarded stage that
**succeeds** disarms the guard:

```jsonc
// chain.json — the year is optional, the rest of the record is not
[
  ["try", "skip"],
  ["re", "search", ["(\\d{4})", 1]],
  ["py","int"]
]
```

The scopes are **constants / shared / private**: `globals` is the chain's read-only constants,
`public` is the run's own notes (writable from any node, never fingerprinted), and `locals` is one
field's scratch space.

```bash
uv run up2 lint chain.json                                   # compile-time validation (does not execute)
uv run up2 trial chain.json --input 'text=announcement published 2026-09' --json
# {
#   "state": "ok",
#   "value": 2026
# }
```

The same shape does the real work on a page — take an attribute, complete the relative link, and
normalise a feed timestamp into one canonical form:

```jsonc
// link.json — the download URL, resolved against the page base
[["css1", "@href", "a.download"], ["py", "urljoin", "$globals.base_url"]]

// date.json — a machine timestamp in, the canonical shape out
[["css1", "text", "time.pubdate"], ["py","normalize_space"], ["py","strptime","%Y-%m-%dT%H:%M:%S%z"], ["py","strftime","%Y-%m-%d %H:%M:%S"]]
```

```bash
uv run up2 trial link.json --global base_url=https://example.com/news/ \
  --input 'text=<a class="download" href="/files/list.pdf">Download</a>' --json
# {
#   "state": "ok",
#   "value": "https://example.com/files/list.pdf"
# }

uv run up2 trial date.json \
  --input 'text=<time class="pubdate">2026-09-24T15:30:00+0800</time>' --json
# {
#   "state": "ok",
#   "value": "2026-09-24 15:30:00"
# }
```

**A finished chain is stored under a business identity** (`04` §1–§6): `publish` is the only write
entry point, it lints the chain again before writing, it keeps one row per `(root_domain, tpl_key)`
and appends a fingerprint to an append-only audit — re-publishing the same chain writes nothing.

```bash
export UP2_HOME=~/.uniparser2            # where the store lives (default); UP2_STORE=sqlite for SQLite
uv run up2 publish link.json --domain ah.gov.cn --key 政府文件列表 --actor llm:claude --source agent
# changed=True chain_id=… 8f8bf3ed… -> d53a2ae0… audit_seq=1

uv run up2 get ah.gov.cn 政府文件列表 --graph > backup.json   # the chain data, as backup material
uv run up2 get ah.gov.cn 政府文件列表                          # the row + its fingerprint
uv run up2 audit ah.gov.cn 政府文件列表                        # who changed it to which fingerprint, and when
```

`--skip-tests` is accepted only with `--note` (the note lands on the audit row), and replacing a row
whose `status` is `ready` needs `--confirm-overwrite`.

**The snapshots in `samples/` are the regression the publish gate runs** (`04` §6 G2, §7-S4/S5). A
sample case is a directory — `input.txt` plus the `expected.json` that `--accept` freezes:

```bash
uv run up2 snapshot link.json --domain ah.gov.cn --key 政府文件列表 --case list-2026-09 --accept
uv run up2 test ah.gov.cn 政府文件列表          # every case of that key; a mismatch prints, e.g. /0/title
uv run up2 publish link.json --domain ah.gov.cn --key 政府文件列表   # refuses a red set: UP2-E3005
uv run up2 doctor [--fix]                       # chains and audit in step? --fix writes a missing audit row
```

A case that carries an `input.txt` but no snapshot is **red**, so a chain cannot quietly stop being
regressed; passing `--skip-tests --note "…"` is the documented way past a red set, and the note is
what the audit row records. The committed example is
[`samples/local/demo/`](samples/local/demo/site.json).

Python API:

```python
import uniparser2 as up2

chain = up2.compile_field(
    [
        ["re", "search", [r"(\d{4})-(\d{2})", 1]],
        ["py", "int"],
    ]
)

scope = up2.Scope(globals={"base_url": "https://example.com"})
outcome = up2.eval_field(chain, "published in 2026-09", scope=scope)

match outcome:
    case up2.Ok(value=value):
        print(value)  # 2026
    case up2.Failed(code=code, reason=reason, fix=fix):
        print(code, reason, fix)  # deterministic error code + one-line remedy; the run failed
```

**There are two outcomes, not three.** A query that matched nothing is a **value** — the empty value
of its shape (`""` / `[]` / `None`) — so the chain carries on; a stage that *fails* stops the chain and
is reported with its code. There is no "missing" state to match on.

**A step's `type` is a shape** (`03` §3): the host registers name → constructor with
`register_type(name, constructor)`, and the kernel builds it from the product at the **step boundary**.
The constructor is a **validator, not a container** — the product keeps flowing as JSON: a dictionary
product is `Cls(**payload)`, a list product `Cls(*items)`, an unregistered name is `UP2-E1011` at that
step, and a constructor that raises is `UP2-E2019` with its own exception text in `reason`:

```python
from dataclasses import dataclass

import uniparser2 as up2


@dataclass
class Article:  # the fields are the product's keys; a missing title fails here, not at the exit
    url: str
    title: str
    pub_time: str = ""


up2.register_type("Article", Article)
bundle = {
    "entry": "record",
    "steps": [
        {
            "name": "record",
            "body": {"url": ["$in", ["py", "getattr", "url"]], "title": [["css1", "text", "h1"]]},
            "type": "Article",
        }
    ],
    "collect": "record",
}
run = up2.start(bundle, response)  # a missing `title` fails here, not at the exit
```

A bad chain gets a deterministic diagnostic with a pointer at **compile time**, instead of exploding
halfway through a run. The diagnostic is one line with a fixed shape — error code, message, position,
remedy — and `lint` exits non-zero:

```text
<UP2-E****>: <message> | at <JSON Pointer> | fix: <one-line remedy>
```

Two examples of that same shape, both measured on this repository: a step whose length does not match
the operator's arity reports `UP2-E1004` at `/0`; a missing required parameter reports `UP2-E1005` at
the parameter's own slot (for example `/0/2`). `$?` is `1` in both cases.

## Development

```bash
uv sync                     # create the virtualenv and install dev dependencies
uv run pytest --cov=uniparser2.core --cov-fail-under=95   # tests + kernel coverage gate
uv run up2 conformance --check   # conformance audit: every (operator, action) declared in the registry must have a case
uv run ruff format --check && uv run ruff check
uv run mypy                 # strict
uv build                    # build sdist + wheel
```

Two scripts stay outside the package and are run from the repository root: `uv run python demo.py`
(the walkthrough above) and `uv run python tools/demo_report.py`, which renders a catalogue of every
declared `(operator, action)` pair from a real run — `.cache/report/up2-report.html` locally, or
`--md` for the committed [`docs/report/up2-report.md`](docs/report/up2-report.md). The committed
catalogue is refreshed from the test suite:

```bash
uv run pytest tests/report                          # fails when the catalogue is stale
UP2_UPDATE_REPORT=1 uv run pytest tests/report      # rewrites it instead
```

The repository-facing reference is the hand-maintained
[`docs/operator-reference.md`](docs/operator-reference.md).

**The conformance audit is the backbone of this project**: it turns "every piece of syntax is covered
by tests" into a mechanically checkable criterion — every `(operator, action)` declared in the registry
must have a visible coverage declaration in the test sources, and every implemented error code must be
asserted by at least one case. Adding an operator and forgetting its case is caught immediately.

The checks to run after a change — and when — are listed in the engineering note
([`docs/specs/005` §6](docs/specs/005-engineering-workflow.md)); they must all be green before you commit.
